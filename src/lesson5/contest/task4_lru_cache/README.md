# Задача D. LRU-кеш

Кеш хранит не больше `c` пар «ключ — значение». Когда нужно добавить новый ключ, а кеш заполнен, из него удаляется ключ, к которому дольше всего не обращались (Least Recently Used). Обращением считаются команды `GET` и `PUT` для этого ключа.

| Команда | Действие | Вывод |
|---------|----------|-------|
| `GET k` | найти значение по ключу `k` | значение или `MISS` |
| `PUT k v` | записать значение `v` по ключу `k` | `OK` или `EVICT e` |

Подробнее:

- `GET` для ключа, который есть в кеше, — попадание (hit): печатается значение, ключ становится самым свежим. Иначе — промах (miss): печатается `MISS`, кеш не меняется.
- `PUT` для ключа, который уже есть в кеше, заменяет значение, делает ключ самым свежим и печатает `OK`.
- `PUT` для нового ключа при неполном кеше добавляет его и печатает `OK`. Если кеш заполнен, сначала удаляется самый давний ключ `e`, затем добавляется новый, печатается `EVICT e`.

После всех команд выведите строку `HITS h MISSES m` — число попаданий и промахов команд `GET`.

## Ввод

В первой строке целые числа `c` и `q` — ёмкость кеша и количество команд.

В следующих `q` строках по одной команде.

## Вывод

Для каждой команды одна строка с ответом, затем строка со статистикой.

## Ограничения

- `1 ≤ c ≤ 100 000`
- `1 ≤ q ≤ 200 000`
- ключ — от `1` до `10` строчных латинских букв
- `|v| ≤ 10^9`

## Пример

Ввод:

```
2 9
PUT a 1
PUT b 2
GET a
PUT c 3
GET b
GET c
PUT a 10
PUT d 4
GET a
```

Вывод:

```
OK
OK
1
EVICT b
MISS
3
OK
EVICT c
10
HITS 3 MISSES 1
```

## Подсказка

Напишите обобщённый класс `LruCache<K, V>`. Каждая операция должна работать за `O(1)`: перебор всех ключей при каждом вытеснении не пройдёт большие тесты. Подойдёт `LinkedHashMap` с порядком обращений: конструктор `LinkedHashMap<>(capacity, 0.75f, true)`, самый давний ключ — первый при обходе.
